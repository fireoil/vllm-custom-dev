CHAPTER 02

环境安装与第一次推理

🔖 vLLM v0.31.0🔧 动手实验
本章目标：把 vLLM 装好、跑通两条路线（服务化 / 离线脚本），并且看得懂启动日志。全程提供小显存显卡（8GB）方案和纯 CPU 验证方案。

2.1环境要求速查

项目要求说明
操作系统Linux（推荐）/ WSL2 / macOS(实验性)生产环境基本都在 Linux
Python3.10 ~ 3.14（v0.31 要求 >=3.10,<3.15）建议 3.10~3.12
CUDA12.8+（pip 安装的轮子自带 CUDA 运行时）nvidia-smi 看驱动即可
显存跑本教程实验：6GB 够用（0.5B 模型）8GB 舒服，24GB 自由
磁盘≥ 20GB（轮子约 2GB + 模型缓存）模型默认缓存在 ~/.cache/huggingface

先检查你的机器（本教程演示机已验证）：

bash
python3 -V                 # 本机: Python 3.10.12
nvidia-smi                 # 本机: NVIDIA GeForce RTX 4060 Laptop GPU
df -h ~ | tail -1          # 家目录剩余空间
没有 NVIDIA 显卡？ 依然可以完成 80% 的学习：所有 🔧 原理模拟器（lab/ 下）纯 Python 运行；vLLM 也有 CPU 版（pip install vllm --extra-index-url https://download.pytorch.org/whl/cpu），用 0.5B 模型跑通流程没问题，只是速度慢。第 07 章多卡实验除外。

2.2安装

方式一：pip 安装（推荐学习用）

bash
# 建议先建虚拟环境，避免污染系统
python3 -m venv ~/venvs/vllm-lab
source ~/venvs/vllm-lab/bin/activate

# 安装最新版（v0.31.0）
pip install -U vllm

# 国内网络可用镜像加速：
pip install -U vllm -i https://pypi.tuna.tsinghua.edu.cn/simple

安装完验证：

bash
python -c "import vllm; print(vllm.__version__)"
# 输出 0.31.0 即成功（首次 import 会编译一些内核缓存，属正常）

方式二：Docker（推荐生产 / 想要干净环境）

bash
docker run --gpus all -it --rm \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  -p 8000:8000 \
  vllm/vllm-openai:v0.31.0 \
  --model Qwen/Qwen2.5-0.5B-Instruct

常见安装问题

症状原因解法
pip install 卡在下载 torchtorch 约 2.5GB换镜像源；或耐心等
RuntimeError: Found no NVIDIA driver驱动没装/WSL2 未装 GPU 驱动宿主机装最新驱动，nvidia-smi 能看到卡即可
CUDA error: out of memory显存不够/被别的进程占用关掉其他程序；降低 gpu_memory_utilization
import 很慢 / 第一次启动 1~2 分钟编译 Triton/CUDA Graph 缓存正常现象，二次启动变快

2.3路线一：一条命令起服务（vllm serve）

bash
vllm serve Qwen/Qwen2.5-0.5B-Instruct \
  --max-model-len 2048 \
  --gpu-memory-utilization 0.85

第一次运行会从 HuggingFace 下载模型（约 1GB）。国内网络可先设镜像：

export HF_ENDPOINT=https://hf-mirror.com

看懂启动日志（重要！后面章节全靠它）

启动时会打印一段极有信息量的日志，这是你了解 vLLM 内部的第一个窗口：

启动日志（节选）
INFO ... Initializing a V1 LLM engine ...
INFO ... model weights take 0.99 GiB          ← 模型权重占多少
INFO ... KV Cache size: 2.68 GiB              ← 预留给 KV Cache 的显存
INFO ... # GPU blocks: 7971                   ← KV Cache 被切成多少个"块"！
INFO ... Maximum concurrency: 31.16x          ← 理论上能同时服务 31 个满长度请求

逐条解读（对应后面章节）：

  • # GPU blocks: 7971：KV Cache 显存 ÷ 每块大小（16 token/块）。这是 PagedAttention 的"座位总数"（第 04 章）。
  • Maximum concurrency: 31.16x：可用块数 × 每块token数 ÷ max_model_len，即"如果每个请求都撑满 2048 token，能同时坐 31 个"。
  • 如果日志出现 CUDA out of memory 或 blocks 数异常小，通常是 gpu_memory_utilization 设太高或 max-model-len 太大。

发起第一次请求

另开一个终端：

bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen2.5-0.5B-Instruct",
    "messages": [{"role": "user", "content": "用一句话解释什么是vLLM"}],
    "max_tokens": 64
  }'

能收到 JSON 回复即成功。这是兼容 OpenAI API 的接口——任何支持 OpenAI 格式的客户端（LangChain、openai SDK、ChatBox 等）都能直接连。

2.4路线二：离线推理脚本（学习原理主要用这条）

生产用服务化，但做实验用离线接口更方便（不涉及 HTTP，变量少）：

lab/first_run.py
# lab/first_run.py —— 你的第一个 vLLM 程序
from vllm import LLM, SamplingParams

# 1. 创建引擎：加载模型 + 预分配 KV Cache（这一步做了什么，第04章揭晓）
llm = LLM(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    max_model_len=1024,
    gpu_memory_utilization=0.85,
)

# 2. 采样参数：控制"怎么生成"
sp = SamplingParams(temperature=0.0, max_tokens=64)

# 3. 生成！注意 prompts 是列表 —— 一次喂多个请求，这就是批处理
prompts = [
    "用一句话解释什么是大语言模型",
    "写一句关于大海的诗",
    "1+1等于几",
]
outputs = llm.generate(prompts, sp)

# 4. 看结果
for out in outputs:
    print(f"prompt : {out.prompt[:20]}...")
    print(f"output : {out.outputs[0].text}")
    print(f"生成了 {len(out.outputs[0].token_ids)} 个 token\n")

运行：

bash
python lab/first_run.py

两个必懂概念（第一次写代码就会遇到）

SamplingParams 常用参数：

参数含义什么时候调
temperature随机度，0=每次都一样（贪心）机器翻译/代码 → 0；写诗 → 0.8+
max_tokens最多生成多少 token防止失控；压测时配合 ignore_eos
top_p / top_k只从概率最高的前若干候选中采样一般不动
stop遇到某字符串就停工具调用场景

LLM vs AsyncLLM（重要伏笔）：

  • LLM(...) → 同步离线接口，generate() 一把梭（本教程实验用它）
  • AsyncLLM → 异步接口，是 vllm serve 的心脏，支持流式输出（第 03/06 章详讲）

2.5动手实验清单

✅ 实验 2-1（必做）：跑通 first_run.py，把 prompts 换成 8 个问题，观察输出顺序。

✅ 实验 2-2（必做）：起 vllm serve，抄下日志里的 # GPU blocks 数值。然后改参数重跑一次，把数字填进表格——你现在就能预测它们的趋势：

参数变化# GPU blocksMaximum concurrency
基准：--gpu-memory-utilization 0.85________
调大：--gpu-memory-utilization 0.92________
调大：--max-model-len 4096________

预期：调大 utilization → blocks 变多；调大 max-model-len → concurrency 变小。

如果你的观察和预期一致，说明你已经"从外部摸到了"vLLM 显存管理的规律。
