第 10 章 · 接入自己的模型
CHAPTER 10

定制开发：接入自己的模型 / 修改 vLLM 行为

🔖 vLLM v0.31.0🔧 动手实验
本章目标：走出"使用"，进入"改造"。覆盖四个层级的定制，由浅入深：①换 tokenizer/模板 ②加参数改行为 ③注册自己的模型架构 ④写自己的注意力后端。这是本课程的毕业章——学完你就是"vLLM 二次开发工程师"。

10.0定制层级地图

层级场景难度本章小节
L1 配置级换聊天模板、改采样默认值⭐10.1
L2 插桩级观察内部、拦截请求/输出⭐⭐10.2
L3 模型级支持一个新模型架构⭐⭐⭐⭐10.3
L4 内核级自定义注意力后端/算子⭐⭐⭐⭐⭐10.4

总原则：能用 L1 不用 L2，能用 L2 不用 L3。（改得越深，跟上游版本同步的成本越高。）

10.1L1 配置级定制

换聊天模板（最高频需求）

vLLM 默认用 HuggingFace 模型仓库里的 tokenizer_config.json 里的 chat template。自建模型/特殊格式时，用 --chat-template 指定自己的 jinja2 模板：

bash
vllm serve my-model --chat-template /path/my_template.jinja
my_template.jinja
{# my_template.jinja 最小示例 #}
{%- for m in messages %}{%- if m.role == 'user' %}[用户]: {{ m.content }}
[助手]:{% endif %}{%- endfor %}

修改采样默认值 / 参数白名单

服务层面改默认采样（如强制 temperature 上限）：在 vllm/entrypoints/openai/ 协议校验处（protocol.py）拦截；更干净的方式是前面加一层网关改写请求。

10.2L2 插桩级定制：不改文件的钩子

第 06 章的 monkeypatch 就是这一级的工具。两个实用模板：

python
# 钩子1: 拦截所有进引擎的 prompt(做审计/改写)
import vllm.v1.engine.async_llm as am
orig = am.AsyncLLM.add_request
async def audited_add(self, request_id, prompt, params, **kw):
    print(f"[audit] {request_id}: {str(prompt)[:50]}")
    return await orig(self, request_id, prompt, params, **kw)
am.AsyncLLM.add_request = audited_add

另一个官方姿势是 plugin 机制（vllm.general_plugins 入口点组）：写一个包，在 pyproject.toml 里注册 [project.entry-points."vllm.general_plugins"]，vLLM 启动时自动加载——适合给团队做"无侵入"增强（自定义平台、注册模型、改平台检测等，这正是 vLLM 上游希望你扩展的方式）。

10.3L3 模型级定制：让 vLLM 跑起你的新架构

先问自己：真的需要写代码吗？

vLLM 的模型注册是按 architectures 名字匹配的。若你的模型只是"改了权重的 Llama"，不用写一行代码：

python
# 只要 HF config.json 里 architectures 是 vLLM 已支持的架构名, 直接就能跑:
vllm serve /path/to/my-finetuned-llama   # finetune 不改变架构 → 直接支持

真正的新架构：四步接入

源码主战场：vllm/model_executor/models/registry.py + models/ 目录。

text · 接入四步示意
Step 1  写模型类
        在 vllm/model_executor/models/ 下新建 my_model.py:
        - 定义 MyModel(nn.Module), forward(input_ids, positions, intermediate_tensors)
        - 注意力必须用 vLLM 的统一层: from vllm.v1.attention... / model_executor.layers.attention
          (自动接入调度器的 block_table 与 FlashAttention 后端 —— 第04/06章的机制在此接通)
        - 实现 load_weights(weights): 把 HF safetensors 的权重名映射到自己的模块
        - 附带 MyModelInfo: 告诉 vLLM 这个架构的参数规约(层数/头数从 config 读取的规则)

Step 2  注册
        registry.py 里 _MODELS 注册表加入: "MyModelForCausalLM": ("my_model", "MyModel")

Step 3  让 HF config 能被识别
        config.json 的 architectures 写上 "MyModelForCausalLM", model_type 相应登记

Step 4  验证
        vllm serve /path/to/my-model
        # 对照启动日志: 加载权重 → profile → blocks 分配 → 出第一个 token
自定义模型接入全流程四步接入拆成 9 步逐步走读 · 对应 10.3 节

最省力的学习路径：抄一个结构最近的现成实现（如 llama.py 只有几百行），改名换骨。vLLM 300+ 个模型实现都是这么互相抄出来的。

定制采样行为（不改模型）

想要新的采样参数？路径：SamplingParams（vllm/sampling_params.py）→ vllm/v1/sample/ 采样器中添加你的 logits 处理步骤 → OpenAI 协议层（entrypoints/openai/protocol.py）暴露字段。

10.4L4 内核级：自定义注意力后端（了解即可）

当新架构有特殊注意力（如自定义稀疏模式）：

  • 位置：vllm/v1/attention/backends/，实现 AttentionBackend 抽象类（interface.py）：核心是 build_metadata() —— 把调度器给的 block_table 翻译成你内核需要的元数据；内核函数按 4.2 的块结构读 KV；
  • 参考实现：flash_attn.py（主路径）、flashinfer.py；
  • 通常需要 CUDA/Triton 内核配合，属于深度定制，绝大多数团队到 L3 为止。

10.5定制开发工作流（避免踩坑）

  1. 先在 vLLM 的 GitHub issue 搜：你想要的改动 90% 有人提过/做过；
  2. 开发用可编辑安装：git clone 源码 → pip install -e . → 改代码即时生效；
  3. 测试：vllm/model_executor/models/ 对应模型有 test_*；跑 pytest tests/v1/ 相关子集；
  4. 升级策略：定制代码集中在自己的文件 + 少量注册点，上游升级时只处理注册点冲突；
  5. 给上游提 PR：vLLM 社区对新模型 PR 非常活跃，贡献进去 = 永久免除维护负担。

10.6动手实验（毕业设计）

🚀 实验 10-1：注册一个"克隆模型"

bash
# 1. 找到 vLLM 源码目录(第03章方法), 复制 llama.py 为 myclone.py
# 2. 全局替换类名 LlamaForCausalLM → MyCloneForCausalLM (注意同步改 registry 注册)
# 3. 用一个 Qwen2.5-0.5B 的目录, 把 config.json 的 architectures 改成
#    ["MyCloneForCausalLM"](Qwen2 架构与 Llama 同构, 权重可直接跑)
# 4. vllm serve 后能正常对话 = 你的第一个 vLLM 模型接入完成 🎓
这个实验看似"作弊"，实则走通了 L3 的全部机制：注册表匹配 → 模型类实例化 → load_weights 映射 → 调度器/注意力后端自动接通。真新架构只是把第 2 步的"抄"变成"写"。

🔬 实验 10-2：给采样器加一个自定义 logits 处理

在 vllm/v1/sample/ 找到采样器组装处，插入一个"禁用某个特定 token"的处理，验证输出中该 token 消失。（做结构化输出/敏感词过滤时会用到同类机制。）
